# Evo Token Readable font

This experiment maps each effective 16-bit TI-84 Evo token word to one
OpenType glyph. The glyph visually spells the token's human-readable form, so
the single codepoint `U+E43F` displays as `sin(`, for example.

Here, **Evo is the successor model to the CE**. Evo has its own 16-bit token
system; references to legacy tokens mean the CE-era token encoding used for
conversion compatibility. Evo is not a CE Python Edition variant.

Open [preview.html](preview.html) to search the map, enter raw token words,
inspect their little-endian bytes, and compare the font glyph with the
detokenized text. The page works directly from this directory, although a
local HTTP server gives browsers the most predictable font-loading behavior:

```sh
python3 -m http.server 8766 --directory tools/evo-token-font
```

Then visit <http://127.0.0.1:8766/preview.html>.

## What is encoded

The map is generated by passing every possible word from `0000` through
`FFFF` through `EvoFormat::detokenize_evo_token_words`. A word is included if
the current implementation recognizes it through any of these paths:

- the named `EvoTokens.inc` table;
- an accepted displayable UCS-2 character;
- a private display alias or a special/ranged mapping in `EvoFormat.cpp`;
- a direct legacy-token mapping used by `EvoFormat.cpp`;
- the explicit `0000` end-of-stream token.

Unknown words whose only representation is their own `\uNNNN` fallback are
not included. In the current tree this produces **1,422 mapped words**, not
just the 1,109 unique recognized values contributed by `EvoTokens.inc`.

The generated files are:

- `EvoTokenReadable-Regular.ttf` — installable TrueType/OpenType font;
- `EvoTokenReadable-Regular.woff2` — compressed web font used by the preview;
- `evo-token-map.json` — enriched, human-readable map;
- `evo-token-map.js` — the same map for a preview that also works from
  `file://`;
- `preview.html` — dependency-free interactive explorer.

## Semantic limitation

This is a visualization font, not a replacement source-text encoding. The
glyph that looks like `sin(` remains one codepoint. Copy/paste, searching,
screen readers, string length, selection, and text-processing APIs see
`U+E43F`, not the four visible characters. Font fallback can also expose the
underlying private-use character if this font is not loaded.

Only recognized words receive cmap entries. Undefined Evo words deliberately
fall through to `.notdef` or another font instead of looking like supported
tokens. The font cannot by itself recover byte order; Evo token streams store
each 16-bit word little-endian.

`U+0000` has a cmap glyph but text stacks commonly consume NUL before shaping,
so the preview may show an empty glyph cell for EOS. The readable column still
labels it explicitly.

## Rebuilding

First build the library objects, then compile and run the mapping generator:

```sh
make -j8
c++ -std=c++20 -DTH_GDB_SUPPORT=1 -Isrc -Ivendor/pugixml \
  tools/evo-token-font/generate_mapping.cpp \
  src/*.o src/TypeHandlers/*.o vendor/pugixml/pugixml.o \
  -o /tmp/generate_evo_token_font_mapping
/tmp/generate_evo_token_font_mapping \
  tools/evo-token-font/evo-token-map.json
```

Install FontTools and Brotli into an isolated environment, and download the
SIL-OFL Noto source fonts used to compose the outlines:

```sh
python3 -m venv /tmp/evo-font-venv
/tmp/evo-font-venv/bin/pip install fonttools brotli

curl -L https://raw.githubusercontent.com/notofonts/noto-fonts/main/hinted/ttf/NotoSansMono/NotoSansMono-Regular.ttf -o /tmp/NotoSansMono-Regular.ttf
curl -L https://raw.githubusercontent.com/notofonts/noto-fonts/main/hinted/ttf/NotoSans/NotoSans-Regular.ttf -o /tmp/NotoSans-Regular.ttf
curl -L https://raw.githubusercontent.com/notofonts/noto-fonts/main/hinted/ttf/NotoSansSymbols/NotoSansSymbols-Regular.ttf -o /tmp/NotoSansSymbols-Regular.ttf
curl -L https://raw.githubusercontent.com/notofonts/noto-fonts/main/hinted/ttf/NotoSansSymbols2/NotoSansSymbols2-Regular.ttf -o /tmp/NotoSansSymbols2-Regular.ttf
curl -L https://raw.githubusercontent.com/google/fonts/main/ofl/notosansmath/NotoSansMath-Regular.ttf -o /tmp/NotoSansMath-Regular.ttf
curl -L https://raw.githubusercontent.com/notofonts/noto-fonts/main/hinted/ttf/NotoMusic/NotoMusic-Regular.ttf -o /tmp/NotoMusic-Regular.ttf
```

Build the font and enriched browser map:

```sh
/tmp/evo-font-venv/bin/python tools/evo-token-font/build_font.py \
  --mapping tools/evo-token-font/evo-token-map.json \
  --output-dir tools/evo-token-font \
  --source-font /tmp/NotoSansMono-Regular.ttf \
  --source-font /tmp/NotoSans-Regular.ttf \
  --source-font /tmp/NotoSansSymbols-Regular.ttf \
  --source-font /tmp/NotoSansSymbols2-Regular.ttf \
  --source-font /tmp/NotoSansMath-Regular.ttf \
  --source-font /tmp/NotoMusic-Regular.ttf
```

Validate both generated font formats against the effective map:

```sh
/tmp/evo-font-venv/bin/python tools/evo-token-font/validate_font.py
```

Six mapped words currently require an explicit visual fallback because their
readable form uses compatibility or private characters absent from Noto. The
JSON records these in `fontFallbacks`, and the explorer surfaces a warning for
the selected token. The authoritative `readable` value is never changed.
